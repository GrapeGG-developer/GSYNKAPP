# GSYNK 2.3.1

Обновление-починка: приложение больше не падает ни при нажатии NFC, ни при открытии
«Датчиков». Оба вылета найдены по отчётам, которые прислал сам телефон.

## Вылет 1: нажатие NFC

По отчётам с телефона (два сбоя 13.10.2026, 19:24):

```
IllegalStateException: Vertically scrollable component was measured with an
infinity maximum height constraints, which is disallowed
```

Экран сопряжения Grape Link (открывается касанием NFC → «Открыть комнату»)
завёл **свою вертикальную прокрутку внутри `GrapeScreen`**, который уже
прокручивает содержимое. Compose такие вложения запрещает и останавливает
приложение — отсюда падение сразу при открытии сопряжения.

### Что исправлено

- Своя прокрутка убрана: содержимое сопряжения живёт внутри общей.
- Новый сторож **`ScrollGuardTest`** (4 теста) читает исходники интерфейса и не даст
  вернуть ни свою прокрутку внутри `GrapeScreen`, ни список без собственной высоты.
  Он же проверяет два законных случая (блок с ограниченной высотой и чат с явной
  высотой) — ложных срабатываний нет.

## Вылет 2: «Лаборатория железа» → датчики

Отчёт 13.10.2026, 19:29 (Xiaomi, Android 16):

```
SecurityException: Permission Denial: service from com.gsynk.app.debug asks to run as
user -2 ... requires INTERACT_ACROSS_USERS_FULL
  at android.hardware.SystemSensorManagerImpl.registerAonListener
```

Android 16 отдаёт «always-on» датчики (AON) через отдельную системную службу, куда
обычному приложению входа нет. Мы подписывались сразу на все датчики телефона — и
получали остановку процесса.

### Что исправлено

- Появился фильтр `DeviceLab.isSystemOnlySensor`: подписка идёт только на публичные
  датчики; приватные (тип ≥ 0x10000) и всё, что помечено как AON, отсекаются до подписки.
- Карточка **«Только для системы»** показывает список таких датчиков и их число — честно
  сообщая, что прочитать их не может ни одно обычное приложение (и не должна).
- 4 новых теста в `LabToolsTest`.

### Почему фильтр стоит везде

Третий отчёт из той же пачки (19:31) поймал тот же сбой, но уже во время работы с
вибро-шаблонами: исключение AON всплывает **отложенно**, из обработчика главного
потока, поэтому обернуть подписку в `runCatching` бесполезно — процесс умирает позже
и в другом месте. Единственная защита — на системный датчик не подписываться. Поэтому
фильтр стоит во всех точках: список всех датчиков, магнитометр (индукция и поиск
металла) и акселерометр (уровень).

- Новый сторож **`SensorGuardTest`** (5 тестов) читает исходники и не даст добавить
  новую подписку на датчик без фильтра.
- В журнал пишется, сколько датчиков пропущено и как они называются: если что-то ещё
  стрельнёт, следующий отчёт сам назовёт виновника.
